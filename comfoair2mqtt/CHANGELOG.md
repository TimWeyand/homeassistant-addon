# Changelog

## 0.1.6
- **Fix: crash loop when using a manual external MQTT broker (`ValueError: int('')`):**
  - The service-discovery fallback that fills MQTT port/keepalive only runs when the `mqtt` option is left **empty**. As soon as a broker is configured manually, `export_config 'mqtt'` exports only the sub-keys the user actually set — so omitting `port`/`keepalive` (the common case) left them blank in `config.ini`. Upstream `ca350.py` runs `int(MQTTPort)`/`int(MQTTKeepalive)` at import time, so a blank value crashed startup with `ValueError: invalid literal for int() with base 10: ''` — the same restart-loop symptom as the original `KeyError: 'DEVICE'`, just on the manual-broker path.
  - The entrypoint now defaults `MQTTPort=1883` and `MQTTKeepalive=45` when unset (matching the discovery path) and logs a warning if a manual `mqtt` config has no host. User-provided values are never overridden.
- **Debug: dump the generated `config.ini` to the add-on log when `debug` is enabled** (MQTT password masked), so "settings not applied" issues are diagnosable straight from the log without shelling into the container.
- Audit confirmed all 24 config keys read by the pinned upstream `ca350.py` (`[DEFAULT]`/`[DEVICE]`/`[MQTT]`/`[HA]`) are generated by the entrypoint, with matching section names and boolean (`== 'True'`) value formats. Pinned upstream is byte-identical to current upstream HEAD — no new keys to track. Upstream code remains untouched.
- **Build hygiene: repo-wide `.gitattributes` forces LF line endings.** The repo is edited on Windows (`core.autocrlf=true`); without this, a Windows checkout would bake CRLF into `docker-entrypoint.sh` and the generated `config.ini` (`MQTTPort=1883\r` → `int()` `ValueError`) — re-introducing the same crash class from the container side.

## 0.1.5
- **Fix: control/sensors dead after the 0.1.4 update (`KeyError: 'DEVICE'`):**
  - The image rebuild for 0.1.4 re-cloned the (unpinned) upstream, which meanwhile made a `[DEVICE]` config section (fan levels) mandatory. Our entrypoint only generated `[DEFAULT]`/`[MQTT]`/`[HA]`, so `ca350.py` crashed at startup before connecting to MQTT — every Comfoair entity went `unavailable` and could no longer be controlled. The 0.1.4 supervisor loop masked this as a silent restart storm instead of a hard failure.
  - The entrypoint now generates the required `[DEVICE]` section in `config.ini`.
  - New add-on options `fan_levels.*` (out/in absent/low/mid/high) and `setup_fan_levels_at_start` expose the upstream fan-level feature, defaulted to upstream values. `setup_fan_levels_at_start` defaults to **false** so the unit's fan calibration is **not** reprogrammed on boot (preserves prior behavior). Normal climate/level control does not depend on these values.
- **Fix: self-healing supervisor never actually looped (broken since 0.1.4):**
  - The entrypoint runs under bashio (`set -o errexit`). A bare `wait "${child_pid}"` on the crashing `ca350.py` aborted the script before the loop could iterate, so the "restarting in Ns" log, the backoff, and the `HEALTHY_RUNTIME` reset never ran — instead the whole container restarted every few seconds (exactly the `KeyError: 'DEVICE'` banner-loop seen in the add-on log).
  - Fixed with `rc=0; wait "${child_pid}" || rc=$?`, and `|| true` on the `term_handler` kill/wait so a clean SIGTERM stop exits 0.
- **Reproducible builds — upstream is now pinned:**
  - The `git clone` of [hacomfoairmqtt](https://github.com/adorobis/hacomfoairmqtt) is pinned to a verified-compatible commit (`ARG HACOMFOAIRMQTT_REF`) instead of tracking HEAD, so a rebuild can no longer silently break the config contract again.
  - `paho-mqtt` is pinned to `>=2.1,<3` (the pinned upstream uses the v2 callback API).
- Upstream code itself remains untouched — this stays a wrapper-level change.

## 0.1.4
- **Self-healing supervisor (no more manual restarts):**
  - The add-on entrypoint now runs `ca350.py` inside a restart-supervisor loop instead of as a one-shot command
  - If the script ever exits — e.g. an MQTT failure or an unhandled serial exception terminates it — it is automatically restarted after 10s, so the add-on recovers without a manual restart
  - Clean stops from Home Assistant (SIGTERM/SIGINT) break the loop instead of restarting (proper `trap` handling, no orphaned child process)
  - **Exponential backoff (10s → 300s)** on restarts: a permanently missing serial device no longer causes a 10s restart storm. A healthy run (≥60s) resets the backoff so ordinary crashes still recover quickly
  - The upstream [hacomfoairmqtt](https://github.com/adorobis/hacomfoairmqtt) code is left completely untouched — this is a wrapper-level change only

## 0.1.3 and earlier
- Wrapper around [hacomfoairmqtt](https://github.com/adorobis/hacomfoairmqtt): exposes its configuration in Home Assistant, provides a working Python environment, and installs/runs the upstream `ca350.py`.
